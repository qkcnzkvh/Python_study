웹 개발 기초 (Web)
웹 서비스란?
- 인터넷 위에서 표준 규약을 통해 자원과 정보를 제공하는 시스템
- 웹 서비스
  - 약속된 규칙을 기반으로 인터넷을 통해 제공되는 서비스
웹의 기본 동작 원리
사용자 → UI → 클라이언트(기기) → 인터넷 → 서버 → 데이터베이스
- Request (요청): 클라이언트가 서버에 특정 기능이나 데이터를 요구하는 것
- Response (응답): 서버가 요청을 처리한 결과를 클라이언트에 전달하는 것
네트워크와 인터넷
- 네트워크(Network): 컴퓨터들이 서로 연결된 구조
- 인터넷(Internet): 여러 네트워크가 서로 연결된 네트워크들의 네트워크
IP와 PORT
IP (Internet Protocol)
- 네트워크상에서 컴퓨터나 장치를 식별하는 주소
Port
- 하나의 IP에서 여러 서비스가 동시에 실행될 때 프로그램을 구분하는 번호
- IP만 있으면 컴퓨터까지 도착
- Port까지 있어야 어떤 서비스인지 정확하게 전달 가능
자주 사용하는 포트
포트	용도
80	HTTP
443	HTTPS

자주 사용하는 IP 주소
- 192.168.0.1: 일반적으로 공유기 관리 페이지에서 사용하는 사설 IP 주소
- 127.0.0.1: 자기 자신의 컴퓨터를 가리키는 루프백 IP 주소(Localhost)
DNS (Domain Name System)
- 도메인 이름을 IP 주소로 변환해 주는 시스템
- 인터넷의 전화번호부와 같은 역할

HTTP와 HTTPS
HTTP (HyperText Transfer Protocol)
- 클라이언트와 서버가 요청과 응답 메시지를 주고받는 방법을 정한 통신 규칙
- 웹에서 데이터를 주고받을 때 사용하는 프로토콜
HTTPS
- HTTP에 보안 기능을 추가한 통신 프로토콜
- 데이터를 암호화하여 안전하게 통신할 수 있도록 지원
HTTPS의 암호화 방식
1. 대칭키 암호화
- 하나의 키로 암호화와 복호화를 모두 수행
- 송신자와 수신자가 같은 키를 공유
- 암호화 및 복호화 속도가 빠름
- 키를 안전하게 전달하기 어려움
2. 공개키 암호화
- 공개키와 개인키를 사용
- 공개키로 암호화한 데이터는 대응하는 개인키로 복호화
- 연산 속도가 상대적으로 느림
- 공개키를 공개적으로 전달할 수 있어 키 교환에 유리함
3. HTTPS의 암호화 방식
- 대칭키와 공개키 암호화를 함께 사용하는 하이브리드 방식
- 서버의 인증서와 공개키를 검증한 후 안전하게 세션 키를 교환
- 이후 실제 데이터 통신은 대칭키 암호화를 사용
참고: 인증서에는 서버의 공개키와 도메인 등의 정보가 포함되며, CA(Certificate Authority)는 인증 기관을 의미한다.
HTTP 기본 메서드
HTTP 메서드는 일반적으로 대문자로 작성한다.
메서드	역할
GET	자원 조회
POST	자원 생성
PUT	자원 전체 수정
PATCH	자원 일부 수정
DELETE	자원 삭제

Query Parameter
- URL에 데이터를 붙여서 전달하는 방식
- 주로 조회 조건이나 옵션을 표현할 때 사용
- 경로(Path) 뒤에 ?key=value 형태로 추가
예시:
https://www.google.com/search?q=python


- ? : Query Parameter 시작
- q : 매개변수 이름
- python : 전달하는 값
REST API
REST (Representational State Transfer)
- 웹 API를 설계하기 위한 아키텍처 스타일
- 자원을 중심으로 URL을 설계하고 HTTP 메서드를 사용하여 자원을 처리하는 방식
RESTful

- REST의 설계 원칙을 잘 따르는 API를 의미

API (Application Programming Interface)

- 서로 다른 소프트웨어가 정보를 주고받을 수 있도록 정한 인터페이스

인터페이스(Interface)

- 서로 다른 대상이 소통하기 위해 미리 정해 둔 규칙이나 접점

REST API 관리
- 백엔드 개발자가 API 설계와 일관성을 책임짐
- 프론트엔드 개발자는 정해진 API 명세에 따라 요청을 보냄

프론트엔드와 백엔드
Front-end
사용자가 직접 보는 화면과 상호작용을 구현하는 영역

주요 역할
- 사용자가 보는 UI 구현
- 사용자의 입력(클릭, 입력 등) 처리
- 사용자 행동을 HTTP 요청으로 변환
- 서버 API 응답을 받아 화면에 반영
- 사용자 경험(UX)을 고려하여 상호작용 설계
UX (User Experience)
- 사용자가 서비스를 이용하면서 느끼는 전반적인 경험
- 사용자가 직관적으로 예상하고 편리하게 사용할 수 있도록 설계하는 것
주요 기술
- HTML
- CSS
- JavaScript
Back-end
서버에서 동작하는 기능과 데이터 처리를 구현하는 영역

주요 역할
- 프로그래밍 언어를 이용한 비즈니스 로직 구현
- 웹 프레임워크를 활용한 요청 및 응답 처리
- 서버와 데이터베이스를 활용한 데이터 처리
- 서비스의 핵심 기능과 구조 관리

데이터와 데이터베이스
데이터(Data)
- 가공되지 않은 사실이나 값
정보(Information)

데이터베이스(Database)

SQL (Structured Query Language)

Git & GitHub
Git이란?
- 버전 관리를 위한 도구(프로그램)
- 내 컴퓨터에서 동작
- 프로젝트의 변경 사항을 기록하고 관리
- 이전 버전으로 돌아가거나 여러 버전을 비교할 수 있음
GitHub란?
- Git 저장소를 온라인에 올려두는 웹 서비스
- 코드 공유 및 협업 플랫폼
- 여러 개발자가 함께 프로젝트를 진행할 수 있도록 지원
Git 기본 용어
Repository (저장소)
- 파일과 변경 이력을 함께 관리하는 저장소
- 프로젝트 전체와 모든 버전 기록이 들어 있음
종류
- Local Repository: 내 컴퓨터에 있는 저장소
- Remote Repository: GitHub 같은 서버에 있는 저장소
Commit
- 변경 사항을 하나의 기록으로 저장하는 단위
- 현재 작업 내용을 확정하고 기록하는 행위
- 커밋이 쌓이면서 프로젝트의 버전 이력이 만들어짐
Branch
- 독립적으로 작업할 수 있는 작업 공간
- 기존 코드를 직접 수정하지 않고 별도로 개발할 수 있음
브랜치 관리 전략
브랜치	역할
main	배포 가능한 안정적인 버전
dev	개발 중인 기능을 통합하고 테스트하는 버전
feature	새로운 기능을 개발하는 브랜치
hotfix	긴급한 오류를 수정하는 브랜치

브랜치 기본 명령어
# 브랜치 생성
git branch 브랜치명

# 브랜치 전환
git switch 브랜치명

# 브랜치 생성 후 바로 이동
git switch -c 브랜치명

# 브랜치 병합
git merge 브랜치명

# 브랜치 삭제
git branch -D 브랜치명


브랜치 병합 방식
1. Fast-Forward (빨리 감기)
- 병합할 브랜치가 현재 브랜치의 최신 커밋을 기반으로 이어져 있을 때 사용
- 별도의 병합 커밋 없이 브랜치의 포인터만 이동
예시:
commit1 → commit2 → commit3
                         ↑
                        main


feature 브랜치의 커밋을 병합하면 main이 해당 커밋을 가리키게 됨.

2. 3-Way Merge
- 두 브랜치가 서로 다른 방향으로 작업되었을 때 사용
- 공통 조상 커밋과 각 브랜치의 변경 사항을 비교하여 병합
- 일반적으로 병합 커밋이 생성됨
3. Conflict (충돌)
- 동일한 부분을 서로 다르게 수정했을 때 발생할 수 있음
- Git이 자동으로 병합할 수 없는 상황
- 사용자가 충돌 부분을 직접 수정해야 병합 가능
HEAD
- 현재 내가 작업 중인 위치를 가리키는 포인터
- 일반적으로 현재 체크아웃된 브랜치의 최신 커밋을 가리킴
Working Directory
- 실제 파일을 작업하고 수정하는 공간
- 아직 Git에 기록되지 않은 변경 사항이 존재할 수 있음
Staging Area
- 다음 커밋에 포함할 변경 사항을 미리 모아두는 공간
- git add 명령어로 변경 사항을 추가
Git 기본 명령어
저장소 생성 및 설정
# Git 저장소 초기화
git init

# 현재 상태 확인
git status

# master 브랜치를 main으로 변경
git branch -m master main

# 기본 브랜치를 main으로 설정
git config --global init.defaultBranch main


파일 관리 및 커밋
# 파일을 Staging Area에 추가
git add 파일명

# 모든 변경 파일 추가
git add .

# 커밋 생성
git commit

# 커밋 메시지를 바로 작성
git commit -m "커밋 메시지"

# 커밋 기록 확인
git log


git commit 실행 시 Vim 편집기가 열리는 경우
1. i를 눌러 입력 모드 활성화
2. 커밋 메시지 작성
3. Esc를 눌러 입력 모드 종료
4. :wq 입력 후 Enter
5. 커밋 완료
원격 저장소 연결 및 동기화
# 원격 저장소 연결
git remote add origin 깃허브주소

# 원격 저장소로 업로드
git push origin main

# 원격 저장소의 변경 사항 가져와 병합
git pull origin main

# 원격 저장소의 프로젝트 복제
git clone 깃허브주소


GitHub 협업 기능
Issue
- 협업 중 발생한 문제나 작업 내용을 등록하는 기능
- 작업 담당자를 배정하거나 진행 상황을 관리할 수 있음
Pull Request (PR)
- 작업한 브랜치의 내용을 다른 브랜치에 병합해 달라고 요청하는 기능
- 코드 리뷰 및 검토 후 병합 가능
